# KO帰属集計 確定仕様 v2

承認日: 2026-11-04。ユーザーのゲーム仕様説明・追加訂正と修正プランへの実装依頼を根拠とする。Guild Battle / Grand Battle共通。

## 入力の意味と前提

- KO値は現在勝ち残っている1部隊の連勝KO数で、ギルド累計ではない。1秒ごとの戦闘終了時にまとめて更新される。
- 教会（ID6〜21）の最低配置数は2体、城（ID2〜5）・神殿（ID1）は3体、最大5体。次の対戦相手は最低配置数以上の未損耗部隊である。
- 勝ち残り部隊は損耗して残存1体になり得る。全滅しなかった側の途中損失は集計対象外。
- 部隊数は全滅でだけ減り、任意に追加される。撤退・取り消しによる減少はない。
- 通常の連続更新は最大1戦と推定する。WebSocketの全件通知保証は未確認であり、検出不能な欠落による誤推定リスクは残る。

## 判定契約

| 候補 | KO条件 | 加算 |
|---|---|---|
| 戦闘なし | 前後同値、両側の部隊数が減っていない | なし |
| 継続勝利 | 差分が教会2〜5、城・神殿3〜5 | 同じ被KO側へ差分 |
| 勝者交代 | 新値1〜5 | 反対の被KO側へ新値 |

戦闘ありの部隊差分は、被KO側が−1以上、他方が0以上（全滅1部隊と追加で説明可能）であること。成立する候補をすべて残す。ギルドの日累計を帰属確定の閾値にしない。現在の連勝KOが6以上なら単戦の交代直後ではないが、攻防のどちらかまでは確定しない。

- 現在の被KO側ごとに最大2候補。各候補は未加算の防衛・侵攻・合計それぞれの最小/最大を保持する。同じ側へ合流する履歴は各成分の最小/最大で統合する。
- 全候補に共通して確実な防衛・侵攻の最小値だけを累計へ加算し、全候補から加算済み量を差し引く。合計範囲からも同じ合計を差し引く。二重加算・減算・根拠のない暫定帰属を禁止する。
- 初回値は基準のみ。切断・再起動・ギルド交代・KO0へのリセットでは旧保留を未確定終了とし、新しい基準を取る。ギルド交代前の累計は旧ギルドへ保持する。
- 成立候補がなければモデル不整合を記録して基準を取り直す。欠落分の復元・推測加算はしない。通信は継続する。

## 保存・互換性

- 確定分を次の5秒保存周期へ含める。保留中の表示増加は保証しない。城別攻防とギルド合計は同一snapshot・transactionで公開し、30秒条件で遅延させない。
- checkpoint schemaVersion 2。v1と同一バトルでの途中切替は禁止し、既存データを保全して終了。次バトルでv2初期化。v2再開では保存済み累計を維持し、観測基準を取り直す。
- 不明形式・破損は保全。既存公開パス/field、排他、世代管理、非同期保存、終了上限は維持。GBM画面は変更しない。
- 新方式開始後はv2対応版で復旧する。過去の欠損・誤加算は再計算しない。

## 解析・受入条件

- 5秒周期で拠点種別/最低人数、城/ギルドID、前後のKO/部隊数、候補、確定加算、保留範囲、理由を記録する。最大128判定/周期、超過数を記録。raw payloadは出さない。
- 保存完了はrevision・対象・所要時間を記録。30秒進捗とsummaryに確定累計・保留/未確定終了範囲・不整合数を含める。
- 正常例: 教会7→9→11、城/神殿7→10→13は継続。帰属既知で2→3は交代、城/神殿2→4は交代、教会2→4と両方の2→5は条件次第で保留。10→1の交代、部隊減少付き同値KOも検証する。
- 後続確定・二重加算防止、初回/区間境界、5秒公開、codec往復/破損保全/v1拒否、fencing、停止/再接続を検証。独立の全履歴列挙と範囲圧縮方式を比較する。
- Step8: 新判定モデルと参照テスト（本番切替なし）。Step9: 集計・v2保存・5秒公開へ統合。Step10: 解析ログ・全体検証・運用資料。
- 各Stepのtest/typecheck成功後にローカルコミット。最終build/Emulator/Windows・Linux CIを確認し、未実行を明示。push/deploy/WF起動/本番書き込みは別途明示指示が必要。
